## 图的读法

- 左侧主线自上而下：用户层 → 统一门户 → 平台服务层（任务/资产/质量/复核四个中心）→ 执行层（SAS 9.4 受控节点 + R/Python 容器）→ 数据层（数仓唯一入口 → 受控数据区）→ 环境分层（DEV/VAL/PROD）→ 基础设施。
- 右侧红色虚线框是**治理与合规**，贯穿所有层：元数据模型、审计库、权限模型、CSV 验证。
- 设计原则：一期做薄——先把"任务能跑、日志能查、差异能比、全程留痕"做扎实，避免大药企踩过的"过度监管"坑。

## 关键架构决策点（待拍板）

1. SAS 许可与部署形态（9.4 Server / Viya，核数与并发）——成本上限
2. 自建 vs 采购边界：执行/留痕自建，校验用 Pinnacle 21
3. 环境分层：三套环境 + 受控晋升机制
4. 元数据模型早定：study/program/run/output/version
5. 与临床研发数仓的接口契约：只读快照 + 版本标识

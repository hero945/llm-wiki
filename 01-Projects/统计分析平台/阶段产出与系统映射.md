# 阶段产出与系统映射：是决策还是代码

## 四类产出

1. **决策类**：选型、边界、责任分工 → 产出是文档，不进系统，但决定系统形态
2. **契约类**：接口、数据格式、元数据模型 → 先文档，随后变成代码里的表结构和 API
3. **系统类**：平台本身的代码（任务引擎、门户、QC 工具）
4. **证据类**：验证文档、审计报表 → 不是代码，但系统必须能生成它们

## 映射表

| 事项 | 产出物 | 性质 | 映射到系统哪里 |
|---|---|---|---|
| 摸底现状 | 资产清单 | 决策输入 | 决定资产中心要不要做迁移导入 |
| SAS 许可测算 | 许可方案 | 纯决策+采购 | 执行层计算节点（买来的，不是写的） |
| 数仓接口契约 | 数据契约文档 | 契约 | 数据层"数仓→受控数据区"的接口代码 |
| CSV 验证对齐 | 验证责任矩阵 | 纯决策/流程 | 反向约束发布流程（版本冻结） |
| 首批场景确认 | 场景清单+验收标准 | 纯决策 | 决定一期开发范围 |
| 目标架构图 | 架构图 | 决策表达 | 每个框 = 一个待建/待购组件 |
| 元数据模型 | 实体关系定义 | 契约（关键） | 直接变成平台数据库表结构 |
| 自建 vs 采购 | 边界清单 | 纯决策 | 质量中心集成 P21 而非自研校验 |

## 一期代码只写三样

1. **任务引擎**（队列 + worker + 日志捕获）——核心代码
2. **差异比较**（回归测试框架）——最容易出亮点
3. **审计留痕**（append-only 日志）——合规底线，量小但不能省

其余：买（SAS、P21）、借（Git、SSO）、刻意做薄（门户、复核流）。

## 首批场景的代码形态

- SAS 执行 = 批处理调用：`sas -sysin 程序 -log 日志 -print 清单`，成败看日志不看退出码
- 日志扫描 = 规则匹配（ERROR / WARNING / 未初始化变量），规则表做成可配置
- 差异比较 = 两层：数据集级包装 `proc compare`；输出级 RTF/PDF 文本 diff
- 共用底座 = 运行记录表（元数据模型最小实现）+ 任务队列 + 不可变结果目录

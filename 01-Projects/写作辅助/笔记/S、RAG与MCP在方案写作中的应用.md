# S. RAG 与 MCP 在方案写作中的应用

> 本文档解释 RAG 和 MCP 的区别，以及它们在 M11 方案写作系统中的具体应用场景和引入节奏。
> 定稿日期：2026-08-20

---

## 1. RAG 能做什么

**RAG（Retrieval-Augmented Generation）= 检索增强生成**

模型生成之前，先从知识库中检索相关片段，把片段塞进 Prompt 里作为参考。

### 1.1 在 M11 方案写作中的用途

| 场景 | 具体做法 | 价值 |
|---|---|---|
| **历史方案参考** | 检索公司过去 10 份类似适应症的方案，提取常用句式 | 保持公司写作风格一致 |
| **M11 模板匹配** | 检索 ICH M11 官方模板对应章节的要求 | 确保不遗漏章节要素 |
| **公司 SOP 对齐** | 检索内部医学写作 SOP、术语表 | 避免使用禁用词 |
| **IB 信息补充** | 从研究者手册中检索药物机制、安全性信息 | 写背景/药物管理章节有依据 |
| **法规指南引用** | 检索 ICH E9(R1)、E6(R2) 等指南原文 | 估计目标、统计分析描述更规范 |
| **竞品方案参考** | 检索已公开的同类药物方案 | 设计选择有参照 |

### 1.2 RAG 的局限

- 只能**读**，不能**改**
- 知识新鲜度取决于索引更新频率
- 检索质量决定生成质量（Garbage in, garbage out）

---

## 2. MCP 能做什么

**MCP（Model Context Protocol）= 模型上下文协议**

Anthropic 推的标准，现在是 AI 连接外部工具的"USB-C"。模型可以通过 MCP 调用外部工具/服务，既能读也能写。

### 2.1 在 M11 方案写作中的用途

| 场景 | 具体做法 | 价值 |
|---|---|---|
| **连接术语管理系统** | 自动查公司标准术语，替换非标准写法 | 术语一致性 |
| **连接药物数据库** | 查询药物剂量、适应症、禁忌症 | 写药物管理章节 |
| **连接统计计算工具** | 调用 R/Python 计算样本量、把握度 | 第 10 章统计方法更准确 |
| **连接法规数据库** | 查询最新 ICH/FDA/NMPA 指南 | 法规描述不过时 |
| **连接审阅系统** | 自动创建审阅任务、记录修改意见 | 工作流自动化 |
| **连接版本控制系统** | Skill 升级后自动提交 Git、触发回归测试 | 反馈闭环自动化 |
| **跨系统一致性检查** | 查询 CTMS 中的实际入排标准，对比生成内容 | 减少方案与实际执行偏差 |

### 2.2 MCP 的局限

- 需要现有 API/工具可连接
- 调试复杂，错误会传播
- 需要权限和审计

---

## 3. RAG vs MCP 对比

| 维度 | RAG | MCP |
|---|---|---|
| **核心能力** | 从文档中检索知识 | 连接工具/API 执行任务 |
| **数据方向** | 只读 | 可读可写 |
| **数据新鲜度** | 依赖索引更新 | 实时 |
| **适用问题** | "这个内容应该怎么写？" | "我需要查/算/改什么？" |
| **技术复杂度** | 中（向量库 + 检索） | 高（API 集成 + 权限） |
| **在本项目阶段** | 阶段二引入 | 阶段三或按需引入 |

## 4. 在系统中的分层架构

```
┌─────────────────────────────────────┐
│           AI Agent / 编排层          │  ← 决定什么时候检索、什么时候调工具
├─────────────────────────────────────┤
│  RAG 知识层        │   MCP 工具层   │
│  · 历史方案库      │   · 术语系统   │
│  · M11 模板        │   · 药物数据库 │
│  · 公司 SOP        │   · 统计计算   │
│  · 法规指南        │   · 审阅系统   │
│  · IB 文档         │   · Git/CI     │
└─────────────────────────────────────┘
```

## 5. 什么时候引入

### 5.1 阶段一（1-2 月）：不做

原因：
- 数据量小，Prompt 里直接放示例和规则就够了
- 先把端到端跑通
- 但 Prompt Builder 要预留 `context_documents` 字段

### 5.2 阶段二（2-4 月）：引入 RAG

优先场景：
1. **历史方案库检索**：为每个 Skill 找到 3-5 份相似示例
2. **IB 文档检索**：写背景/药物管理章节时引用
3. **SOP/术语表检索**：确保用词符合公司规范

技术栈：
- 向量库：Milvus / Qdrant / pgvector
- Embedding：Qwen2.5-1M 或国产 embedding 模型
- 分块策略：按章节/段落分块，保留章节标签

### 5.3 阶段三（4-6 月）：引入 MCP

优先场景：
1. **术语管理 MCP**：自动替换非标准术语
2. **统计计算 MCP**：调用 R 计算样本量
3. **Git/CI MCP**：Skill 升级自动触发回归测试
4. **审阅系统 MCP**：自动同步修改意见

## 6. 一个具体例子

假设要写第 5 章"试验人群"：

**不用 RAG/MCP：**
- Prompt 里只有当前摘要的入排标准
- 模型可能写得比较单薄

**用 RAG：**
- 检索历史 3 份类似适应症的方案
- 把它们的入排标准写法作为参考
- 生成内容更丰满、风格一致

**用 MCP：**
- 调用术语系统，把"中重度斑块型银屑病"替换为公司标准术语
- 调用 CTMS 查询实际入组人群的年龄分布
- 自动检查入排标准是否与统计分析计划一致

## 7. 对我们的启示

2026 年研究显示：**base LLM 做临床指南问答准确率只有 36-50%，但加上 RAG/MCP 后显著提升**。

| 阶段 | 策略 |
|---|---|
| 阶段一 | 用强模型 + 好 Skill 建立 baseline |
| 阶段二 | 加 RAG，把质量从 60% 提到 75% |
| 阶段三 | 加 MCP，把一致性和自动化提到 85%+ |

RAG 是**性价比最高**的下一步，MCP 是**自动化最深**的下一步。

# 12. 反馈闭环设计

> 本文档记录 M11 方案生成 Copilot 的反馈闭环设计：如何采集医学专家修改、分类原因、生成 Skill 补丁并验证。
> 定稿日期：2026-08-20

---

## 1. 闭环目标

把医学专家的修改转化为系统改进：

1. 识别修改点
2. 分类修改原因
3. 判断能否规则化
4. 生成 Skill 补丁或更新元数据
5. 回归测试验证

---

## 2. 闭环流程

```
AI 生成章节
   ↓
医学专家在 Word 中修改（修订模式）
   ↓
上传修改版
   ↓
解析 w:ins / w:del
   ↓
差异片段映射到章节/段落
   ↓
反馈分析器分类
   ↓
人工确认分类
   ↓
├─ 可规则化 → 生成 Skill 补丁 → Git 提交新版本
└─ 项目特例 → 更新元数据/示例
   ↓
回归测试验证质量提升
```

---

## 3. Word 修订解析

### 3.1 解析目标

从 Word 文档中提取：
- 插入内容（`w:ins`）
- 删除内容（`w:del`）
- 修改位置（段落、章节）
- 修改者身份（可选）
- 修改时间（可选）

### 3.2 解析器接口

```python
class RevisionDiff(BaseModel):
    diff_id: str
    chapter_id: str
    paragraph_index: int
    revision_type: str     # insert / delete
    original_text: str | None
    revised_text: str | None
    author: str | None
    timestamp: datetime | None

class RevisionParser:
    def parse(self, file_path: str) -> list[RevisionDiff]:
        ...
```

### 3.3 阶段二范围

- 先支持段落级文本修订
- 表格、复杂格式修订暂不支持，标为待处理

## 4. 反馈分类

### 4.1 分类体系

| 类别 | 说明 | 处理方式 |
|---|---|---|
| **规则缺失** | Skill 规则没有覆盖该场景 | 新增/修改规则 |
| **示例不足** | 示例没有展示类似写法 | 补充示例 |
| **元数据错误** | 提取的元数据不准确 | 更新元数据/提取规则 |
| **格式问题** | Word 样式、排版问题 | 更新渲染器/模板 |
| **项目特例** | 只适用于当前项目的修改 | 更新元数据，不进 Skill |
| **模型幻觉** | AI 编造内容 | 强化禁止项/占位符策略 |
| **无法规则化** | 需要人类判断的创造性修改 | 记录，暂不处理 |

### 4.2 分类器接口

```python
class FeedbackClassifier:
    def classify(self, diff: RevisionDiff, context: dict) -> ClassificationSuggestion:
        ...

class ClassificationSuggestion(BaseModel):
    diff_id: str
    suggested_category: str
    confidence: float
    reasoning: str
```

### 4.3 分类方法

- 规则分类器：基于关键词和模式
- LLM 分类器：让模型根据上下文判断
- 最终由医学专家在 Web UI 中确认

## 5. Skill 补丁生成

### 5.1 可规则化修改的补丁

| 修改类型 | Skill 补丁 |
|---|---|
| 增加一条写作规则 | `writing_rules` 新增一条 |
| 增加禁用词 | `forbidden_patterns` 新增一条 |
| 增加示例 | `examples` 新增一个 |
| 调整输出结构 | `prompt_template` 修改 |

### 5.2 补丁生成器接口

```python
class SkillPatcher:
    def generate_patch(
        self,
        skill: Skill,
        diffs: list[RevisionDiff],
        classifications: list[Classification],
    ) -> SkillPatch:
        ...

class SkillPatch(BaseModel):
    skill_id: str
    base_version: str
    new_version: str
    changes: list[dict]
    risk_level: str     # low / medium / high
```

### 5.3 风险分级

| 风险等级 | 说明 | 处理方式 |
|---|---|---|
| **low** | 新增示例、新增禁用词 | 自动生成，可快速发布 |
| **medium** | 修改写作规则、调整 Prompt | 人工审核后发布 |
| **high** | 修改输出结构、跨章节规则 | 医学专家 + QA 双重审核 |

---

## 6. 项目特例处理

项目特例不进入 Skill，而是：
- 更新该任务的 `confirmed_metadata`
- 补充到该项目的示例库
- 作为未来类似项目的参考

## 7. Web UI 设计

反馈分类确认界面：

```
┌─────────────────────────────────────────┐
│ 修改 #1                                 │
│ 原文：本试验旨在评价...                  │
│ 改后：本试验旨在评估...                  │
│                                         │
│ 分类建议：[规则缺失] 置信度 0.85          │
│ 原因：模型使用了"评价"，规范用法是"评估"  │
│                                         │
│ [确认] [改为：示例不足] [改为：项目特例]  │
│ [忽略此修改]                            │
└─────────────────────────────────────────┘
```

```
   ↓ 回归测试
发布
```

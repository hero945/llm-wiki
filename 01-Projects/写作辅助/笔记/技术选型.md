# 技术选型：前端 / 后端 / 存储 / 模型 / 部署

> 本文档是写作辅助项目的逐层技术选型与默认决策，2026-08-19 定稿。
> 概要表在 [[1、AI方案撰写_竞品分析与架构]] 3.5 节；流程与交互前提见 [[2、项目决策记录]]。

---

## 一、约束条件（决定了 80% 的选型）

1. 单团队单用户、内部工具 → 不需要多租户、微服务、API 网关那一套
2. 任务是异步长流程（解析中 → 待澄清 → 生成中 → 待审阅 → 已完成）→ 需要任务队列与状态持久化
3. 输入输出都是 Word/PDF → 文档处理必须在 Python 生态
4. Skill 是核心资产，Git 管理（已定决策）→ 不进数据库
5. 药企数据敏感 → 模型层必须可替换，为私有化留退路
6. 成本控制"预留不深入" → LLM 调用日志从第一天落库，路由/缓存后做

---

## 二、默认选型清单

| 层 | 默认选型 | 一句话理由 |
|----|----------|------------|
| 前端 | React + TypeScript + Vite + Ant Design，SSE 推进度 | 事实确认工作台 = 大表格 + 分组表单，AntD 组件正好；进度是单向推送，不需要 WebSocket |
| 后端 | FastAPI + 独立 worker 进程，PG `jobs` 表驱动任务状态机 | 任务与状态天然落库，MVP 不引入 Celery/Redis |
| 存储 | PostgreSQL（JSONB 存元数据）+ 本地盘 / MinIO 存文件 | 元数据 schema 快速迭代，JSONB 免改表；保持单一存储系统 |
| 文档 | `python-docx` + `docxtpl` + `PyMuPDF` + `lxml` | 模板渲染、PDF 输入、修订 `w:ins`/`w:del` 解析、Issue 批注锚定 |
| 模型 | LLM 网关双泳道：生成旗舰模型 / 提取轻量模型，调用全量落库 | 质量与成本分层；换底座不改业务代码 |
| Skill | Git 仓 + YAML + Jinja2 + Pydantic 校验 | 已定决策，版本化知识资产 |
| 部署 | Docker Compose 一体化（web / worker / postgres / minio） | MVP 单包交付，即私有化形态 |

---

## 三、后端

- FastAPI 承载全部同步接口；异步生成由独立 worker 进程轮询 `jobs` 表执行
- 任务状态机显式落库：`解析中 → 待澄清 → 生成中 → 待审阅 → 已完成`，前端轮询/SSE 只读这张表
- `jobs` 表字段：状态、进度（章节粒度）、重试次数、错误信息、关联 task_id
- **升级信号**：出现任务并发、定时任务、优先级队列需求时，再迁 Celery + Redis，业务接口不变

## 四、前端

- 任务式交互，五个界面：任务列表 / 上传创建 / 事实确认工作台 / 生成进度 / 交付与反馈
- Ant Design 的 Table、Form、Steps、Tag 直接覆盖事实确认工作台的组件需求
- 进度推送用 SSE（单向、自动重连），不用 WebSocket
- 原文溯源：摘要入库时按段落切分并记录偏移量，前端纯文本渲染 + 高亮，不引入 PDF 在线预览

## 五、存储

- 结构化数据（任务、Issue、反馈、LLM 调用日志）→ PostgreSQL 普通表
- 提取元数据（FactBundle）→ PostgreSQL **JSONB**，schema 迭代期不改表结构，仍可 SQL 查询
- 文件（原始摘要、Word 初稿、修改版）→ MVP 本地盘 + 数据库记路径；私有化时换 MinIO（S3 兼容），代码不改
- **向量库 MVP 砍掉**（历史方案库不在 MVP 范围）；真到企业知识库阶段先用 pgvector，继续保持单存储系统

## 六、模型

### 6.1 双泳道

- **泳道 A（章节生成，质量优先）**：长上下文、中文医学写作质量、指令遵循。候选：Claude / GPT 旗舰、DeepSeek、Qwen-Max、GLM 档
- **泳道 B（提取增强 / 修改分类，成本优先）**：输入短、输出 JSON，用各家轻量模型。硬要求：稳定的结构化输出（JSON Schema / function calling）
- MVP 可单模型起步，但 LLM 调用层从第一天按泳道抽象（`generate()` / `extract()` 不同配置）

### 6.2 调用日志（成本记录决策的落地）

每次调用落库：`task_id, chapter, lane(A/B), model, prompt_tokens, completion_tokens, latency_ms, cost, created_at`。这是将来换模型、做路由、算成本时唯一可信的数据依据。

### 6.3 选型 bake-off（用现成样例，不拍脑袋）

1. 输入：`样例/` 三份 synopsis 的已确认元数据 + 同一个第 3 章 Skill
2. 候选模型各生成一次第 3 章
3. 指标：结构符合度、事实一致性、术语一致性 + 医学写作人员盲评修改比例
4. 产出：泳道 A 默认模型，结果追加到本笔记附录

### 6.4 私有化退路

Prompt 与 Skill 中不写任何绑定特定模型怪癖的逻辑；药企要求数据不出境时，网关配置切到私有化 Qwen/DeepSeek 即可。

## 七、部署

- 四个容器：`web`（FastAPI）、`worker`、`postgres`、（可选）`minio`
- Docker Compose 单包 = MVP 交付物 = 私有化形态，不为将来 SaaS 化提前付出架构成本

---

## 八、切换触发点

| 信号 | 动作 |
|------|------|
| 任务并发上来 / 需要定时与优先级 | `jobs` 表 → Celery + Redis |
| 历史方案库进入范围 | 先 pgvector，规模上来再考虑 Milvus |
| 药企要求私有化 / 数据不出境 | 模型网关切私有化 Qwen/DeepSeek |
| 单团队 → 多团队 | 加认证 / RBAC、MinIO、多租户字段 |
| 日志显示提取类调用占比高 | 泳道 B 换更便宜模型 / 加缓存 |

---

## 九、总原则

**MVP 的技术栈要让"换模型、换存储、换部署环境"都不改业务代码**——这个项目唯一确定会变的，就是这三样。

# 9. 确认工作台设计

> 本文档记录事实确认工作台的设计，目标是最小化用户操作，只展示需要人工确认的字段。
> 定稿日期：2026-08-20

---

## 1. 设计原则

**核心原则：用户尽量少操作。**

- 高置信度字段自动填充，不展示
- 只展示中低置信度字段
- 一键确认常见情况
- 批量修改同类字段
- 必填字段不能为空

---

## 2. 工作台定位

确认工作台位于 **元数据提取** 和 **章节生成** 之间：

```
MetadataExtractor
   ↓
融合层输出 Metadata
   ↓
事实确认工作台（只展示 need_confirm=True 的字段）
   ↓
ConfirmedMetadata
   ↓
Generator
```

---

## 3. 字段分类与展示策略

### 3.1 按置信度分类

| 置信度 | 状态 | 工作台行为 |
|---|---|---|
| ≥ 0.9 | 已确认 | 不展示 |
| 0.7 ~ 0.9 | 建议确认 | 展示，可一键确认或修改 |
| < 0.7 | 必须人工 | 展示，必填 |
| value 为 null | 缺失 | 展示，必填，标红 |

### 3.2 按字段重要性分类

| 分类 | 示例 | 策略 |
|---|---|---|
| 关键字段 | 主要目的、主要终点、估计目标 | 必须确认，不可跳过 |
| 重要字段 | 分期、设计类型、样本量 | 建议确认 |
| 普通字段 | 治疗持续时间、给药频率 | 可批量确认 |

## 4. 界面设计

### 4.1 字段卡片

每个待确认字段显示为一个卡片：

```
┌─────────────────────────────────────────┐
│ 分期                                    │
│ 置信度：0.85  来源：规则+LLM            │
│ 提取值：III 期                          │
│ 原始文本："一项 III 期、随机、双盲..."   │
│ [✓ 正确] [✏ 修改] [? 不清楚]            │
└─────────────────────────────────────────┘
```

### 4.2 批量操作

| 操作 | 说明 |
|---|---|
| **全部正确** | 一键确认所有 ≥0.8 的字段 |
| **仅确认选中** | 批量确认勾选字段 |
| **应用到同类** | 把修改应用到同一 section 的相似字段 |

### 4.3 缺失字段处理

缺失字段显示为红色输入框：

```
┌─────────────────────────────────────────┐
│ 探索性目的 *                            │
│ 状态：缺失                              │
│ 请填写：_____________________________   │
│ [保存]                                  │
└─────────────────────────────────────────┘
```

## 5. 后端 API 设计

### 5.1 获取待确认字段

```http
GET /api/tasks/{task_id}/pending-fields
```

响应：

```json
{
  "task_id": "task-001",
  "pending_fields": [
    {
      "field": "phase",
      "value": "III",
      "confidence": 0.85,
      "source": "rule+llm",
      "raw_text": "一项 III 期、随机、双盲研究",
      "severity": "suggested"
    },
    {
      "field": "exploratory_objectives",
      "value": null,
      "confidence": 0.0,
      "source": "unknown",
      "raw_text": null,
      "severity": "required"
    }
  ]
}
```

### 5.2 提交确认结果

```http
POST /api/tasks/{task_id}/confirm
```

请求体：

```json
{
  "confirmations": [
    {
      "field": "phase",
      "value": "III",
      "action": "confirm"
    },
    {
      "field": "exploratory_objectives",
      "value": ["评估安全性特征"],
      "action": "fill"
    }
  ]
}
```

### 5.3 获取确认后元数据

```http
GET /api/tasks/{task_id}/confirmed-metadata
```

## 6. 数据模型

### 6.1 ConfirmedMetadata

```python
class ConfirmedField(BaseModel):
    field: str
    value: Any
    source: str             # 原始来源
    confirmed_by: str       # 用户 ID
    confirmed_at: datetime
    modified: bool          # 是否被修改过

class ConfirmedMetadata(BaseModel):
    task_id: str
    fields: dict[str, ConfirmedField]
    confirmed_at: datetime
```

### 6.2 数据库表

- `task_metadata`：原始提取结果
- `task_confirmed_metadata`：人工确认后结果
- 分开存储，便于追溯原始提取质量和人工修改历史

## 7. 确认流程

```python
class ConfirmWorkbench:
    def get_pending_fields(self, task_id: str) -> list[MetadataField]:
        metadata = self.metadata_repo.get(task_id)
        return [f for f in metadata.fields.values() if f.need_confirm]

    def confirm(self, task_id: str, confirmations: list[dict]) -> ConfirmedMetadata:
        metadata = self.metadata_repo.get(task_id)
        confirmed = {}
        
        for field_name, field in metadata.fields.items():
            if field_name in confirmations:
                action = confirmations[field_name]
                confirmed[field_name] = ConfirmedField(
                    field=field_name,
                    value=action.get("value", field.value),
                    source=field.source,
                    confirmed_by=current_user.id,
                    confirmed_at=datetime.now(),
                    modified=action.get("modified", False),
                )
            else:
                # 高置信度字段直接采用
                confirmed[field_name] = ConfirmedField(
                    field=field_name,
                    value=field.value,
                    source=field.source,
                    confirmed_by="system",
                    confirmed_at=datetime.now(),
                    modified=False,
                )
        
        return self.confirmed_repo.save(task_id, confirmed)
```

## 8. 异常处理

| 情况 | 处理 |
|---|---|
| 用户跳过必填字段 | 前端校验阻止，后端二次校验 |
| 用户输入格式错误 | 按字段类型实时校验 |
| 会话超时 | 自动保存草稿 |
| 多人同时编辑 | 乐观锁，后提交者看到冲突提示 |

---

## 9. 阶段一范围

阶段一确认工作台只需支持：
- 列表展示待确认字段
- 单个/批量确认
- 必填字段校验
- 保存确认结果

高级功能（如修改历史、版本对比、评论）阶段二再做。

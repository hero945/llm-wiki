# 10. 一致性检查器设计

> 本文档记录 M11 方案生成 Copilot 的一致性检查器设计，用于在生成后校验内容内部一致性和与元数据的一致性。
> 定稿日期：2026-08-20

---

## 1. 模块定位

一致性检查器位于 **Generator** 之后、**Word Renderer** 之前：

```
Generator → ChapterContent
   ↓
Consistency Checker → 新增/更新 Issue
   ↓
Word Renderer → Word 初稿
```

目标：在生成阶段尽早发现事实矛盾、数值不一致、规则违反等问题，减少人工返工。

---

## 2. Issue 分级

| severity | 定义 | 处理方式 |
|---|---|---|
| **blocker** | 必须修复，否则不能导出 Word | 样本量与终点矛盾、主要目的缺失 |
| **warning** | 建议修复，可导出但需标注 | 格式不一致、术语不统一 |
| **info** | 提示信息 | 检测到示例引用 |

---

## 3. 检查规则分类

|---|---|---|
| C001 | 主要终点必须在生成内容中出现 | blocker |
| C002 | 样本量必须是正整数 | blocker |
| C003 | 分期必须是 I/II/III/IV 之一 | blocker |

## 4. 规则引擎设计

### 4.1 规则定义

```python
from pydantic import BaseModel
from typing import Callable

class ConsistencyRule(BaseModel):
    rule_id: str
    name: str
    description: str
    severity: str
    scope: str           # chapter / cross_chapter / semantic
    checker: str         # 对应检查函数名
```

### 4.2 检查器接口

```python
class ConsistencyChecker:
    def __init__(self, rules: list[ConsistencyRule]):
        self.rules = rules

    def check(
        self,
        chapter_content: ChapterContent,
        metadata: dict,
        context: dict | None = None,
    ) -> list[Issue]:
        issues = []
        for rule in self.rules:
            checker = self._get_checker(rule.checker)
            result = checker(chapter_content, metadata, context)
            if result:
                issues.append(result)
        return issues
```

### 4.3 YAML 配置

```yaml
consistency_rules:
  - rule_id: C001
    name: 主要终点必须出现
    severity: blocker
    scope: chapter
    checker: check_primary_endpoint_present

  - rule_id: C004
    name: 治疗条件一致性
    severity: warning
    scope: chapter
    checker: check_treatment_consistency

  - rule_id: C006
    name: 禁用词检查
    severity: warning
    scope: chapter
    checker: check_forbidden_words
```

## 5. 具体检查器实现示例

### 5.1 主要终点出现检查

```python
def check_primary_endpoint_present(
    content: ChapterContent,
    metadata: dict,
    context: dict | None = None,
) -> Issue | None:
    primary_endpoint = metadata.get("endpoints", {}).get("primary")
    if not primary_endpoint:
        return None
    
    if primary_endpoint not in content.content:
        return Issue(
            issue_id="C001",
            severity="blocker",
            field="primary_endpoint",
            message=f"生成内容中未出现主要终点：{primary_endpoint}",
            suggestion="检查生成结果是否遗漏主要终点描述",
        )
    return None
```

### 5.2 禁用词检查

```python
FORBIDDEN_WORDS = ["证明", "证实"]

def check_forbidden_words(
    content: ChapterContent,
    metadata: dict,
    context: dict | None = None,
) -> Issue | None:
    found = [w for w in FORBIDDEN_WORDS if w in content.content]
    if found:
        return Issue(
            issue_id="C006",
            severity="warning",
            field=None,
            message=f"发现禁用词：{', '.join(found)}",
            suggestion="将'证明'改为'评估'",
        )
    return None
```

## 6. 与 Skill 的协作

每个 Skill 可以声明自己的 `consistency_rules`：

```yaml
skill:
  chapter_id: "1.1.1"
  consistency_rules:
    - "主要终点必须与 endpoints.primary 一致"
    - "估计目标中的治疗条件必须与 interventions 一致"
```

系统运行时：
1. 加载全局一致性规则
2. 叠加当前 Skill 声明的规则
3. 执行检查
4. 合并 Issue 列表

---

## 7. 输出处理

检查完成后：
- blocker 数量 > 0：阻止 Word 导出，必须修复
- 只存在 warning/info：允许导出，但需在 Issue 清单中列出
- Issue 清单写入 Word 文档页脚/附录

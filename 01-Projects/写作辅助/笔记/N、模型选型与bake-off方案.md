# N. 模型选型与 bake-off 方案

> 本文档记录 M11 方案生成 Copilot 的 LLM 选型策略、bake-off 方案和评估方法。
> 定稿日期：2026-08-20

---

## 1. 模型选型维度

| 维度 | 权重 | 说明 |
|---|---|---|
| **医学写作质量** | 35% | 术语准确、句式规范、不编造 |
| **指令遵循能力** | 25% | 能否按 Skill 规则、M11 结构输出 |
| **长上下文** | 15% | 能否处理完整方案摘要 + 模板上下文 |
| **成本** | 15% | 每章节 token 成本 |
| **合规/可私有化** | 10% | 能否本地部署或走合规通道 |

## 3. 双泳道模型策略

基于 **generate（质量优先）/ extract（成本优先）** 双泳道：

| 泳道 | 任务 | 推荐模型 | 理由 |
|---|---|---|---|
| **A: generate 生成** | 写 M11 章节 | **Claude Sonnet 4.6/5** | 医学长文本、复杂指令、JSON 输出最稳 |
| **B: extract 提取** | 元数据/估计目标 JSON | **GPT-5.4 / Qwen2.5-1M** | 结构化输出稳，成本低 |

> 阶段一可以先用同一模型跑通，阶段二再拆分。

## 4. bake-off 方案

### 4.1 目标

用同一份输入、同一套 Skill，对比 2-4 个候选模型，选出阶段一默认模型。

### 4.2 测试集

| 样本 | 类型 | 用途 |
|---|---|---|
| 样例 1 | 银屑病（公开/虚构） | 主要终点清晰 |
| 样例 2 | 肿瘤（公开摘要） | 复杂终点 + 估计目标 |
| 样例 3 | 免疫（公开摘要） | 多干预组 |
| 样例 4 | 罕见病（重构摘要） | 样本量小、信息稀疏 |

### 4.3 测试任务

每个模型对每份样例执行：

1. **元数据提取**：输出结构化 JSON
2. **第 1.1.1 章生成**：按 Skill 生成 Markdown
3. **一致性检查**：自身检查 + 交叉检查

### 4.4 评估维度

| 维度 | 自动指标 | 人工指标 |
|---|---|---|
| 事实准确性 | 与输入一致性 | 医学专家逐条核对 |
| 结构符合度 | M11 章节结构匹配 | 医学专家评分 |
| 幻觉/编造 | 占位符比例 | 抽查不可信内容 |
| 写作规范性 | - | 医学写作规范评分 |
| 指令遵循 | Prompt 要求满足率 | 规则违反次数 |
| 成本 | token 数 × 单价 | - |
| 延迟 | 端到端耗时 | - |

| Qwen2.5-1M | | | | | | |
| DeepSeek Medical | | | | | | |

### 淘汰线

- 事实准确率 < 95%：直接淘汰
- 占位符/编造处理不当：扣分
- JSON 输出不稳定：不适合 extract 泳道

## 6. 阶段一默认推荐

| 场景 | 推荐模型 |
|---|---|
| **阶段一默认** | **Claude Sonnet 4.6**（云端可用时） |
| **成本敏感** | GPT-5.4 或 Qwen2.5-1M |
| **合规要求国产/私有化** | Qwen2.5-1M 或 DeepSeek Medical |
| **最高质量不计成本** | Claude Opus 4.8 或 GPT-5.5 |
| **提取任务降本** | GPT-5.4 / Qwen2.5-1M |

### 推荐 Claude Sonnet 4.6 的原因

1. 医学协议生成对准确性和指令遵循要求极高
2. 阶段一数据量小，成本差异可以忽略
3. 先建立质量基准，再优化成本
4. LiteLLM 网关支持随时切换，不绑定

## 7. 国产/私有化路径

### 7.1 何时考虑

- 数据合规禁止云端 API
- 客户要求本地化部署
- 成本压力极大

### 7.2 推荐路径

| 阶段 | 做法 |
|---|---|
| 阶段一 | 云端跑通，网关预留国产模型配置 |
| 阶段二 | 引入 1-2 个国产模型做 bake-off |
| 阶段三 | 根据合规要求，支持私有化部署包 |

### 7.3 私有化部署成本

| 方案 | 配置 | 成本 |
|---|---|---|
| 单卡推理 | RTX 4090 / A10G | ¥8k-20k 一次性 + 电费 |
| 云服务 GPU | A10G 24G | ¥1.5k-2.5k/月 |
| 国产模型 API | Qwen/DeepSeek API | 比 Claude 低 3-5 倍 |

## 8. 模型 fallback 策略

预留 fallback 配置：

```yaml
primary: claude-sonnet-4.6
fallback_1: gpt-5.4
fallback_2: qwen2.5-1m
```

| 条件 | 行为 |
|---|---|
| primary 不可用 | 切 fallback_1 |
| 合规限制 | 切 fallback_2 |
| 成本告警 | 提取任务切便宜模型 |

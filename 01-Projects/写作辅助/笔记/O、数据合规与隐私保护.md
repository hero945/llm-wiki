# O. 数据合规与隐私保护

> 本文档记录 M11 方案生成 Copilot 面临的数据合规问题、风险分级和应对路径。
> 定稿日期：2026-08-20

---

## 1. 输入数据的敏感性分层

| 数据类型 | 敏感度 | 是否含个人信息 | 阶段一是否涉及 |
|---|---|---|---|
| **方案摘要（Synopsis）** | 中 | 通常不含受试者个人信息 | ✅ 是 |
| **研究者手册（IB）** | 中-高 | 不含受试者信息，但含未公开药物信息 | 阶段二 |
| **完整方案草案** | 高 | 可能含研究中心、研究者信息 | 阶段二/三 |
| **真实方案样本** | 高 | 可能含商业机密、研究者信息 | 测试用 |
| **修改后的 Word 文档** | 高 | 可能含审阅者身份信息 | 阶段二 |
| **LLM 调用日志** | 中 | 含完整输入输出 | ✅ 是 |
| **用户操作日志** | 低-中 | 含用户名、操作记录 | ✅ 是 |

**关键判断**：临床试验方案本身通常不含受试者个人信息（PII/PHI），但属于**企业敏感数据**和**潜在商业机密**。

---

## 2. 主要合规风险

| 风险 | 法规依据 | 后果 |
|---|---|---|
| **商业机密泄露** | 保密协议、公司制度 | 法律诉讼、项目损失 |
| **数据出境** | 《数据安全法》《个人信息保护法》 | 行政处罚、暂停项目 |
| **研究者信息泄露** | GDPR（如涉及欧盟）、PIPL | 罚款 |
| **未公开药物信息泄露** | 上市公司信息披露法规 | 内幕交易风险 |
| **生成内容不可审计** | NMPA GCP、ICH E6(R2) | 申报不被接受 |
| **LLM 供应商数据训练** | 供应商合同 | 数据被用于模型训练 |

---

## 3. 跨境数据传输问题

### 3.1 现状

| 情况 | 合规结论 |
|---|---|
| 摘要本身不含个人信息 | 可能不属于"重要数据"出境 |
| 但摘要含未公开药物信息 | 公司可能自行定义为敏感数据 |
| 上传到境外 LLM API | 存在数据出境事实 |
| LLM 供应商日志留存 | 数据在境外存储 |

### 3.2 合规路径

| 路径 | 做法 | 难度 |
|---|---|---|
| **路径 A：境外 API + 公司审批** | 走数据出境安全评估/标准合同备案 | 高 |
| **路径 B：境外 API + 脱敏摘要** | 去除药物名称、适应症、公司信息 | 中 |
| **路径 C：境内 API** | 使用阿里云通义、百度文心、讯飞星火等 | 低 |
| **路径 D：私有化部署** | 本地 GPU/服务器部署开源模型 | 最低 |
| **路径 E：混合模式** | 提取用境内/私有，生成用境外（审批后） | 中 |

---

## 4. 阶段一推荐策略

基于"能跑通优先，但不埋雷"的原则：

### 4.1 默认策略：路径 B + 路径 C

| 场景 | 做法 |
|---|---|
| 技术开发、内部测试 | 使用虚构/公开摘要 + 境外 API |
| 真实数据测试 | 必须经法务/合规审批 |
| 生产使用 | 优先境内 API 或私有化 |

### 4.2 具体措施

| 措施 | 说明 |
|---|---|
| **虚构样本先行** | 阶段一用 X-drug、psoriasis 这类虚构案例 |
| **数据分级审批** | 真实数据上系统前走审批流程 |
| **LLM 供应商合同审查** | 确认不用于训练、有数据删除条款 |
| **调用日志本地化** | prompt/response 只存在本地数据库 |
| **环境隔离** | 开发/测试/生产数据隔离 |

## 5. 日志与审计

这对医药监管很重要。

| 日志类型 | 留存要求 | 用途 |
|---|---|---|
| LLM 调用日志 | 至少 5-10 年 | 审计、质量回溯 |
| 用户操作日志 | 至少 5-10 年 | 审计追踪 |
| Skill 版本日志 | 永久 | 生成内容版本链 |
| 元数据变更日志 | 与方案文档等长 | 事实来源追溯 |

### 5.1 审计追踪要求

每份生成的方案必须能追溯到：
- 输入文件版本
- 使用的 Skill 版本
- 模型名称和版本
- Prompt 模板版本
- 人工确认的字段和修改记录
- 医学专家审阅记录

## 6. 不同部署模式的合规等级

| 部署模式 | 数据出境风险 | 合规成本 | 适用阶段 |
|---|---|---|---|
| 境外公有云 API | 高 | 高 | 仅测试虚构数据 |
| 境内公有云 API | 低 | 低 | 阶段一/二生产 |
| 私有云/本地部署 | 最低 | 中 | 阶段三或高敏感项目 |
| 混合部署 | 中 | 中 | 阶段二/三 |

---

## 7. 本周必须明确的合规问题

| 问题 | 负责方 | 影响 |
|---|---|---|
| 能否用境外 LLM API 处理真实数据？ | 法务/合规 | 决定默认模型 |
| 公司如何定义方案摘要的数据分级？ | 数据安全 | 决定脱敏策略 |
| 是否需要数据出境评估？ | 法务 | 决定时间成本 |
| LLM 调用日志留存年限？ | 质量/合规 | 影响数据库设计 |
| 是否需要电子签名/审计追踪？ | 质量 | 影响前端设计 |

---

## 8. 架构层面的合规设计

系统架构已预留的合规能力：

| 设计 | 合规价值 |
|---|---|
| LiteLLM 网关 | 随时切换不同 provider，不绑定境外 |
| MySQL + MinIO 本地部署 | 数据不出境 |
| 任务/调用日志落库 | 完整审计追踪 |
| Skill 版本管理 | 生成内容可追溯到规则版本 |
| 占位符策略 | 不编造，降低事实错误风险 |

---

## 9. 阶段一合规 checklist

- [ ] 确认测试数据全部为虚构/公开摘要
- [ ] 确认 LLM 供应商不使用数据训练
- [ ] 设计调用日志表时包含完整审计字段
- [ ] 用户认证/权限最小化
- [ ] 数据库备份策略确认
- [ ] 真实数据上系统前必须有审批流程

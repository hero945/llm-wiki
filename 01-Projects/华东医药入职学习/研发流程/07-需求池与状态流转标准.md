# 需求池与状态流转标准

## 1. 目的

需求池与状态流转标准用于把需求准入、PRD、需求评审、开发提测、业务验收、价值复盘串起来，形成统一看板，避免需求散落在聊天记录、会议纪要、个人文档和研发任务中。

## 2. 需求池核心字段

| 字段 | 说明 |
|---|---|
| 需求编号 | 唯一编号 |
| 需求标题 | 一句话描述 |
| 需求类型 | 新功能/优化/报表/权限/流程/合规/问题改造 |
| 需求来源 | 业务/客户/用户/数据/管理要求 |
| 提出人 | 提出需求的人 |
| 提出部门 | 来源部门 |
| 产品负责人 | 跟进 PM |
| 业务负责人 | 业务确认人 |
| 优先级 | P0/P1/P2/P3 |
| 当前状态 | 需求当前阶段 |
| 目标上线时间 | 预期上线时间 |
| 实际上线时间 | 实际上线时间 |
| PRD 链接 | 产品文档 |
| 原型链接 | 原型文件 |
| 评审记录 | 需求评审纪要 |
| 提测说明 | 提测记录 |
| 验收记录 | 业务验收记录 |
| 复盘报告 | 价值复盘报告 |
| 关闭结论 | 达成/部分达成/未达成/拒绝/暂缓 |

## 3. 状态定义

| 状态 | 含义 |
|---|---|
| 待补充 | 需求信息不完整，不能继续流转 |
| 待澄清 | 已登记，等待产品与提出方沟通 |
| 待评估 | 产品正在判断价值、范围、优先级和成本 |
| 待写 PRD | 已确认准入，进入产品方案设计 |
| PRD 编写中 | 产品正在编写 PRD、原型、规则 |
| 待评审 | 评审材料准备完成，等待需求评审 |
| 评审中 | 正在进行评审或评审问题待闭环 |
| 已评审 | 评审通过或有条件通过 |
| 待排期 | 等待研发排期 |
| 开发中 | 研发正在开发 |
| 待提测 | 开发完成，等待提测 |
| 测试中 | 测试正在验证 |
| 待业务验收 | 测试通过，等待业务验收 |
| 业务验收中 | 业务正在验收或验收问题待闭环 |
| 待上线 | 验收通过，等待上线 |
| 已上线 | 功能已上线 |
| 价值复盘中 | 上线后进入观察和复盘 |
| 已关闭 | 需求完成闭环 |
| 已暂缓 | 当前不做，后续观察 |
| 已拒绝 | 明确不做 |

## 4. 状态流转规则

```text
待补充
  ↓
待澄清
  ↓
待评估
  ↓
待写 PRD
  ↓
PRD 编写中
  ↓
待评审
  ↓
评审中
  ↓
已评审
  ↓
待排期
  ↓
开发中
  ↓
待提测
  ↓
测试中
  ↓
待业务验收
  ↓
业务验收中
  ↓
待上线
  ↓
已上线
  ↓
价值复盘中
  ↓
已关闭
```

异常流转：

```text
信息不完整：退回待补充
价值不足：进入已暂缓
需求不成立：进入已拒绝
评审不通过：退回 PRD 编写中
业务验收不通过：退回开发中或 PRD 编写中
复盘未达成：进入二期优化或停止投入
```

## 5. 每个阶段的准入准出标准

| 阶段 | 准入标准 | 准出标准 |
|---|---|---|
| 需求准入 | 有提出人和基本场景 | 问题、目标、影响范围明确 |
| PRD 编写 | 需求已准入 | PRD、原型、规则、验收标准完成 |
| 需求评审 | 材料已提前发送 | 评审通过，问题闭环 |
| 开发 | 评审通过 | 开发完成并自测 |
| 提测 | 自测完成，提测说明完整 | 测试接收 |
| 业务验收 | 测试通过，验收清单完成 | 业务确认通过 |
| 上线使用 | 业务验收通过 | 功能上线并可用 |
| 价值复盘 | 上线满观察周期 | 输出价值结论和后续动作 |

## 6. 看板管理建议

建议至少建立 4 个视图：

```text
1. 全量需求池：查看所有需求状态。
2. 本月重点需求：聚焦 P0/P1/P2。
3. 待处理需求：查看待补充、待澄清、待评审、待验收。
4. 价值复盘视图：查看已上线但未复盘的需求。
```

## 7. 管理要求

```text
1. 每个需求必须有唯一编号。
2. 每个需求必须有当前状态。
3. 状态变化必须有负责人。
4. 已上线不等于已关闭，完成价值复盘后才能关闭。
5. 暂缓和拒绝必须记录原因。
6. P0/P1/P2 需求必须关联 PRD、评审记录、验收记录、复盘结论。
7. 每周至少进行一次需求池例行梳理。
```

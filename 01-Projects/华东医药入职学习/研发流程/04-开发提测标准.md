# 开发提测标准

## 1. 目的

开发提测标准的核心是：研发不是“代码写完就丢给测试”，而是必须在达到可测试状态后，才能正式提测。

一句话：提测不是交差，是把需求从“开发完成”交接到“质量验证”。

## 2. 适用范围

适用于所有需要进入测试阶段的研发交付内容，包括：

```text
1. 新功能开发
2. 功能优化
3. Bug 修复
4. 接口改造
5. 数据报表
6. 权限调整
7. 审批流调整
8. 系统集成
9. 数据库结构变更
10. 配置项变更
```

## 3. 提测基本原则

### 3.1 研发自测先于测试验证

最低要求：

```text
1. 核心流程能跑通。
2. 主要功能点已验证。
3. 明显报错已处理。
4. 接口联调已完成。
5. 数据能正常保存、查询、更新。
```

### 3.2 提测内容必须可追溯

每次提测必须关联：

```text
需求编号
PRD 版本
开发分支/版本号
提测范围
影响模块
测试环境
提测负责人
```

### 3.3 提测范围必须明确

需要说清：

```text
本次提测包含哪些功能；
不包含哪些功能；
哪些是新增；
哪些是修改；
哪些是已知问题；
哪些模块可能受影响。
```

## 4. 提测准入标准

| 准入项 | 标准 |
|---|---|
| 需求已评审通过 | PRD 和验收标准已确认 |
| 代码开发完成 | 本次范围内代码已完成 |
| 研发自测完成 | 主流程和核心场景已验证 |
| 接口联调完成 | 前后端接口可正常调用 |
| 测试环境可用 | 环境、账号、数据准备完成 |
| 数据库变更明确 | 表结构、字段、脚本已说明 |
| 配置变更明确 | 配置项、开关、权限配置已说明 |
| 已知问题列出 | 暂未修复或待确认问题已记录 |
| 影响范围说明 | 说明可能影响的模块和旧功能 |
| 提测说明完整 | 提测单信息齐全 |

如果以上任一关键项缺失，测试可以拒绝提测。

## 5. 研发自测标准

### 5.1 主流程自测

确认核心业务流程完整跑通。

```text
用户登录
↓
进入功能页面
↓
填写/筛选/提交/审批/导出
↓
系统处理成功
↓
数据正确保存或展示
```

### 5.2 权限自测

涉及不同角色的需求，研发必须验证：

```text
1. 有权限用户能进入。
2. 无权限用户不能进入。
3. 不同角色看到的数据范围正确。
4. 不同角色按钮权限正确。
5. 敏感字段展示规则正确。
```

### 5.3 数据自测

涉及数据保存、统计、报表、导出时，必须验证：

```text
1. 新增数据是否正确保存。
2. 修改数据是否正确更新。
3. 删除或作废逻辑是否正确。
4. 查询结果是否符合条件。
5. 报表口径是否符合 PRD。
6. 导出数据是否与页面筛选一致。
```

### 5.4 异常自测

至少覆盖：

```text
1. 必填字段为空。
2. 输入格式错误。
3. 重复提交。
4. 无数据。
5. 无权限。
6. 接口失败。
7. 数据超限。
```

### 5.5 回归自测

如果改动影响旧模块，研发必须说明并完成基础回归。

## 7. 不同类型需求的提测重点

| 类型 | 提测重点 |
|---|---|
| 新功能需求 | 功能完整、主流程跑通、角色权限正确、数据正确产生、异常场景可处理 |
| 功能优化需求 | 优化点符合 PRD、是否影响原有功能、老用户使用习惯、原有数据兼容 |
| Bug 修复 | Bug 是否复现过、修复方案、修复后验证、影响模块、回归范围 |
| 报表/数据需求 | 数据来源、指标口径、筛选条件、统计周期、导出一致性、异常数据处理 |
| 权限类需求 | 菜单、页面、按钮、数据、字段、导出、审批权限 |
| 审批流/状态流需求 | 状态流转、不同状态按钮、审批人、驳回/撤回/作废、通知、操作日志 |
| 系统集成需求 | 接口调用、异常重试、第三方失败处理、数据同步、幂等、日志追踪 |

## 8. 提测结论标准

| 结论 | 标准 | 后续动作 |
|---|---|---|
| 接收提测 | 主流程可用，材料完整 | 进入正式测试 |
| 有条件接收 | 小问题不阻塞测试 | 记录问题后测试 |
| 拒绝提测 | 主流程不可用或材料严重缺失 | 退回研发 |
| 暂缓提测 | 环境、数据、依赖未准备好 | 补齐后重新提测 |

## 9. 测试可拒绝提测的情况

```text
1. 没有提测说明。
2. 测试环境不可用。
3. 核心流程无法跑通。
4. 登录、权限、入口不可用。
5. 研发未完成自测。
6. 提测范围不清楚。
7. 接口文档缺失且影响测试。
8. 测试数据未准备。
9. 已知阻塞问题未说明。
10. PRD 或验收标准未确认。
```

## 10. 冒烟测试标准

测试接收提测前，建议先做 15-30 分钟冒烟验证。

```text
1. 页面能否打开。
2. 登录和权限是否正常。
3. 核心按钮是否可点击。
4. 主流程是否能完成。
5. 数据是否能保存。
6. 列表/详情是否能展示。
7. 无明显系统报错。
8. 接口无大面积失败。
```

## 11. 不同行业提测关注重点

| 行业 | 重点关注 | 提测前必须确认 |
|---|---|---|
| 互联网 | 核心转化链路、高并发场景、活动配置、埋点上报、移动端兼容 | 活动开始/结束状态、异常页面、埋点、灰度配置 |
| SaaS / B 端 | 组织权限、客户配置差异、导入导出、多租户隔离、历史数据兼容 | 客户配置隔离、角色数据权限、导入失败可追踪 |
| 金融 | 金额计算、审批权限、交易记录、审计日志、风险控制、数据一致性 | 金额计算、无越权、关键操作有日志、异常交易处理 |
| 医疗 / 医药 | 审批留痕、研发/质量流程、敏感数据权限、数据准确性、版本追溯 | 流程记录完整、关键数据不可随意修改、修改有原因和日志 |
| 制造 / ERP | 库存、采购、生产计划、成本、主数据、单据状态 | 单据状态流转、库存数量、历史单据兼容、跨模块一致 |

## 12. 管理要求

```text
1. 未完成研发自测，不允许提测。
2. 未提供提测说明，测试可以拒绝提测。
3. 核心流程跑不通，测试可以拒绝提测。
4. 涉及数据库、配置、接口变更，必须在提测说明中写清。
5. 涉及权限、金额、审批、报表的需求，必须说明重点测试范围。
6. 提测后发现重大漏开发，需重新评估排期。
7. 多次提测被退回，需要进行研发自测质量复盘。
```

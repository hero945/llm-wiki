# PRD 产品需求文档标准

## 1. 目的

建立统一的产品需求文档编写标准，让业务、产品、研发、测试、设计对需求目标、范围、规则、验收口径形成一致理解。

PRD 的本质不是“产品说明书”，而是需求从业务意图进入研发交付的执行契约。

## 2. 适用范围

适用于：

```text
1. 新功能需求
2. 功能优化需求
3. 后台管理系统需求
4. 数据报表需求
5. 审批流/流程类需求
6. 权限配置需求
7. 系统集成需求
8. 业务规则调整需求
9. 移动端/小程序/网页端产品需求
```

只要涉及流程、权限、数据、状态、金额、审批、对外客户，就必须写标准 PRD。

## 3. PRD 编写原则

### 3.1 先讲问题，再讲方案

错误写法：

```text
新增客户跟进导出功能。
```

合格写法：

```text
当前销售主管每周需要人工汇总团队客户跟进情况，平均耗时约 2 小时，且容易遗漏超期未跟进客户。本需求希望通过系统导出能力，降低人工整理成本，并提升团队管理效率。
```

### 3.2 范围必须有边界

PRD 必须同时写清楚：

```text
本期做什么
本期不做什么
后续可能做什么
```

### 3.3 规则必须可执行

模糊写法：

```text
普通用户不能看到敏感数据。
```

合格写法：

```text
普通销售只能查看自己负责的客户手机号后 4 位；
销售主管可查看本部门客户完整手机号；
管理员可查看全部客户完整手机号。
```

### 3.4 验收标准必须可验证

不要写：

```text
页面使用正常。
```

要写：

```text
当销售主管选择部门和日期范围后，点击导出，系统生成 Excel 文件，文件内容与当前筛选条件一致，且包含客户名称、负责人、最近跟进时间、跟进状态字段。
```

## 4. PRD 标准结构

```text
1. 文档信息
2. 需求背景
3. 需求目标
4. 需求范围
5. 用户角色
6. 业务流程
7. 功能说明
8. 页面原型说明
9. 字段与数据规则
10. 状态流转规则
11. 权限规则
12. 异常场景
13. 通知与消息规则
14. 数据埋点与指标
15. 验收标准
16. 上线影响范围
17. 风险与依赖
18. 待确认问题
19. 修订记录
```

## 5. 各章节编写标准

### 5.1 文档信息

| 字段 | 说明 |
|---|---|
| 需求编号 | 与需求池编号一致 |
| 需求名称 | 简洁描述 |
| 产品负责人 | PRD 编写和解释人 |
| 业务负责人 | 业务规则确认人 |
| 研发负责人 | 技术方案负责人 |
| 测试负责人 | 测试设计负责人 |
| 文档状态 | 草稿/评审中/已确认/已冻结/已上线 |
| 当前版本 | V0.1/V1.0/V1.1 |
| 创建时间 | 文档创建日期 |
| 更新时间 | 最近修改日期 |

### 5.2 需求背景

必须回答：

```text
1. 当前业务场景是什么？
2. 当前遇到什么问题？
3. 问题影响了谁？
4. 影响程度有多大？
5. 为什么现在要做？
```

### 5.3 需求目标

推荐格式：

```text
通过【产品能力/流程改造】，解决【当前问题】，使【目标指标】达到【目标值】。
```

目标类型：

| 类型 | 示例 |
|---|---|
| 增收 | 提高付费转化率、提升续费率 |
| 降本 | 减少人工处理时间、减少客服工单 |
| 提效 | 缩短审批周期、减少重复录入 |
| 控风险 | 降低权限错误、满足审计要求 |
| 体验 | 降低操作步骤、提升完成率 |
| 数据 | 提升数据准确率、统一统计口径 |

### 5.4 需求范围

必须包含：

```text
本期范围
本期不包含
影响模块
影响角色
影响端口
```

示例：

```text
本期范围：
1. 支持销售主管按部门、负责人、客户状态筛选客户跟进记录。
2. 支持导出当前筛选结果。
3. 导出文件包含客户名称、负责人、最近跟进时间、跟进状态字段。

本期不包含：
1. 不支持自定义导出字段。
2. 不支持定时自动发送报表。
3. 不支持移动端导出。
```

### 5.5 用户角色

| 角色 | 使用场景 | 权限说明 |
|---|---|---|
| 普通销售 | 查看自己客户 | 只能查看本人负责客户 |
| 销售主管 | 管理团队客户 | 可查看本部门客户 |
| 销售总监 | 查看全公司销售数据 | 可查看全部客户 |
| 系统管理员 | 配置权限 | 不参与业务操作 |

### 5.6 业务流程

流程图必须覆盖：

```text
1. 主流程
2. 分支流程
3. 异常流程
4. 审批流程，如有
5. 状态流转，如有
```

流程类需求必须额外说明：

```text
每一步由谁操作
每一步产生什么数据
每一步状态如何变化
每一步是否通知相关人
每一步是否记录操作日志
```

### 5.7 功能说明

每个功能点按照以下结构写：

```text
功能名称：
使用角色：
前置条件：
操作入口：
操作步骤：
系统规则：
异常情况：
操作结果：
```

### 5.8 字段与数据规则

| 字段名称 | 字段类型 | 是否必填 | 默认值 | 取值范围 | 校验规则 | 说明 |
|---|---|---|---|---|---|---|
| 客户名称 | 文本 | 是 | 无 | 1-50 字 | 不允许为空 | 客户主体名称 |
| 客户状态 | 枚举 | 是 | 跟进中 | 跟进中/已成交/流失 | 从字典表读取 | 用于筛选 |
| 最近跟进时间 | 日期 | 否 | 无 | 日期 | 不得晚于当前时间 | 系统生成 |

报表类需求必须写清数据口径。

### 5.9 状态流转规则

| 当前状态 | 触发操作 | 操作角色 | 下一状态 | 是否通知 | 是否记录日志 |
|---|---|---|---|---|---|
| 草稿 | 提交审批 | 申请人 | 待审批 | 是 | 是 |
| 待审批 | 审批通过 | 审批人 | 已通过 | 是 | 是 |
| 待审批 | 审批驳回 | 审批人 | 已驳回 | 是 | 是 |
| 已驳回 | 重新提交 | 申请人 | 待审批 | 是 | 是 |
| 待审批 | 撤回 | 申请人 | 已撤回 | 是 | 是 |

必须说明：

```text
终态是什么？
哪些状态可编辑？
哪些状态可删除？
哪些状态可撤回？
哪些状态进入统计？
```

### 5.10 权限规则

权限规则必须覆盖：

```text
菜单权限
页面权限
按钮权限
数据权限
字段权限
审批权限
导出权限
```

| 角色 | 可查看范围 | 可操作功能 | 不可操作功能 | 特殊说明 |
|---|---|---|---|---|
| 普通销售 | 本人客户 | 新增跟进记录 | 导出、删除 | 手机号脱敏 |
| 销售主管 | 本部门客户 | 筛选、导出 | 删除客户 | 可看完整手机号 |
| 管理员 | 全部数据 | 配置权限 | 无 | 操作需留痕 |

### 5.11 异常场景

必须覆盖：

```text
空数据
无权限
网络失败
保存失败
重复提交
数据超限
字段错误
状态冲突
接口超时
```

### 5.12 通知与消息规则

如果需求涉及通知，必须说明：

```text
通知对象
触发时机
通知渠道
通知内容
是否可关闭
失败是否重试
```

### 5.13 数据埋点与指标

必写内容：

```text
1. 需求目标指标
2. 用户行为埋点
3. 业务结果指标
4. 数据看板口径
5. 复盘时间
```

### 5.14 验收标准

推荐格式：

```text
当【角色】在【条件】下执行【操作】时，系统应【结果】。
```

验收标准必须覆盖：

```text
主流程
权限
字段规则
异常场景
数据口径
状态变化
通知规则
```

## 6. PRD 分级标准

| 类型 | 适用场景 | 必须包含 |
|---|---|---|
| 轻量 PRD | 文案调整、样式微调、简单字段展示 | 背景、调整内容、原型或截图、验收标准 |
| 标准 PRD | 大多数产品需求 | 背景与目标、范围、角色、流程、功能说明、原型、字段规则、权限规则、异常场景、验收标准、上线影响 |
| 复杂 PRD | 审批流、财务/金额、权限体系、数据报表、多系统集成、合规/审计 | 状态流转图、数据口径表、接口依赖、审计日志规则、灰度与回滚要求、风险清单、埋点与复盘指标 |

## 7. PRD 评审前检查清单

```text
1. 需求背景是否说明为什么做？
2. 需求目标是否可衡量？
3. 本期范围和不做范围是否清楚？
4. 用户角色是否完整？
5. 主流程是否完整？
6. 异常流程是否覆盖？
7. 字段规则是否明确？
8. 权限规则是否明确？
9. 状态流转是否完整？
10. 验收标准是否可测试？
11. 数据指标是否能支撑价值复盘？
12. 待确认问题是否列出？
```

## 8. PRD 质量评分标准

| 模块 | 分值 |
|---|---:|
| 背景与目标清晰 | 15 |
| 范围边界明确 | 15 |
| 流程完整 | 15 |
| 规则清楚 | 20 |
| 权限/异常覆盖 | 15 |
| 验收标准可执行 | 15 |
| 指标与复盘完整 | 5 |

## 9. 不同行业 PRD 重点差异

| 行业 | PRD 重点 | 最容易遗漏 |
|---|---|---|
| 互联网 | 用户路径、转化率、页面体验、埋点、AB 测试、活动时效 | 异常状态、埋点、活动结束后的状态 |
| SaaS / B 端 | 组织架构、角色权限、客户配置、数据隔离、导入导出、续费价值 | 不同客户配置差异、权限边界、历史数据兼容 |
| 金融 | 金额计算、审批权限、审计日志、监管口径、风险控制、数据准确性 | 操作留痕、异常回滚、权限变更记录 |
| 医疗 / 医药 | 流程合规、数据准确、审批留痕、权限隔离、质量管理、研发/临床节点 | 流程记录不可篡改、数据变更原因、版本追溯 |
| 制造 / ERP | 主数据、库存、采购、生产计划、成本核算、流程审批 | 边界库存、历史单据、跨部门流程衔接 |

## 10. 管理要求

```text
1. 未关联需求编号的 PRD，不进入评审。
2. 未写清需求背景和目标的 PRD，不进入评审。
3. 未写本期不包含范围的 PRD，不进入评审。
4. 涉及权限、金额、审批、报表的 PRD，必须写规则表。
5. 涉及状态变化的 PRD，必须写状态流转表。
6. 涉及业务价值判断的 PRD，必须写指标和复盘时间。
7. PRD 评审通过后进入冻结状态，后续变更必须记录。
```

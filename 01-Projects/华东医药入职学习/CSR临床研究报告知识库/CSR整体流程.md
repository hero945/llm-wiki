简化流程是这样：

1. **发现候选药物 / 确定新适应症**  
    药企或研究机构先有一个假设：
    - 这个新分子可能治疗某种疾病
    - 或者一个已上市药物可能用于新的适应症
    - 或者需要验证新的剂量、联合方案、人群

这时还没有 CSR，只有科学假设、机制依据、早期实验或真实世界线索。

2. **非临床研究 / 既有证据整理**  
    新药通常要做药理、毒理、药代等非临床研究。

适应症扩展则会整理已有数据，比如：

- 已上市适应症的安全性
- 机制是否支持新疾病
- 早期探索性临床数据
- 文献和真实世界数据

目的是判断：**能不能进人体试验，风险是否可接受。**

3. **制定临床开发计划**  
    研发团队会设计整体路径：
    - 先做 I 期还是直接做 II 期
    - 要做几项关键研究
    - 目标人群是谁
    - 主要终点是什么
    - 对照药或安慰剂怎么选
    - 是否需要中国/美国/欧盟多区域研究

这一步决定后面要产生哪些临床试验。

4. **写临床试验方案 Protocol**  
    每一项临床试验都要有方案。Protocol 是 CSR 的“源头文件”之一。

它规定：

- 研究目的
- 研究设计
- 入排标准
- 给药方案
- 终点
- 样本量
- 统计原则
- 安全性监测
- 访视流程

简单说，Protocol 先回答：**我们打算怎么做这个试验。**

5. **监管/伦理审批**  
    试验开始前，通常要提交给监管机构和伦理委员会。

审批材料可能包括：

- Protocol
- Investigator’s Brochure，研究者手册
- 知情同意书
- 非临床/既有临床资料
- 风险控制方案

通过后才能正式招募受试者。

6. **临床试验执行**  
    研究中心开始筛选、入组、随机、给药、随访。

期间产生大量原始数据：

- 受试者基本信息
- 疗效指标
- 不良事件
- 实验室检查
- 生命体征
- 合并用药
- 方案偏离
- 停药/退出情况

	这些数据最初记录在病历、电子病例报告表 eCRF、实验室系统等地方。

7. **数据管理与医学审核**  
    试验进行中和结束后，要清理数据：
    - 检查缺失值和异常值
    - 发 query 给研究中心确认
    - 编码不良事件和合并用药
    - 核对严重不良事件
    - 确认数据库质量

目标是形成可以分析的“干净数据库”。

8. **统计分析**  
    数据库锁定后，统计团队按 SAP（统计分析计划）分析数据。

输出通常包括：

- TFLs：Tables, Figures, Listings
- 主要终点分析
- 次要终点分析
- 安全性分析
- 亚组分析
- 敏感性分析

这些 TFL 是 CSR 结果章节的主要来源。

9. **医学写作起草 CSR**  
    医学写作团队把 Protocol、SAP、TFL、医学审核意见、方案偏离、安全性信息等整合成 CSR。

CSR 会回答：

- 这项研究为什么做
- 怎么做
- 实际招了哪些人
- 结果如何
- 安全性如何
- 结果是否支持研究目的
- 有哪些限制和解释

10. **内部审阅、定稿、归档**  
    CSR 通常要经过多个角色审阅：
    - 临床负责人
    - 统计师
    - 数据管理
    - 药物警戒/安全性
    - 注册事务
    - 质量/合规
    - 医学写作
    - 项目团队

最终签署、定稿，作为注册申报、内部决策或发表资料的正式证据文件。

所以从新药/适应症到 CSR，大致是：

**科学假设 → 非临床/既有证据 → 临床开发计划 → Protocol → 审批 → 试验执行 → 数据清理 → 统计分析 → CSR 写作 → 审阅定稿**

# 安全性数据流是什么

安全性数据流指临床试验中所有和**受试者安全风险**有关的数据，从现场发现、记录、上报、医学审核、标准化编码、统计分析，到最后进入 CSR 的路径。

它和普通疗效数据不同，因为安全性数据通常不能等试验结束后才处理，很多内容需要实时或近实时评估。

## 典型流程

**受试者发生不良事件 → 研究中心记录 AE/SAE → 上报申办方/安全团队 → 医学审核和编码 → 进入安全数据库/临床数据库 → 统计分析 → 写入 CSR 安全性章节**

## 谁参与

| 角色 | 主要责任 |
|---|---|
| 研究者/PI | 判断、记录和报告不良事件，评估严重性和因果关系 |
| CRC/研究护士 | 协助收集访视信息、录入 eCRF、跟进资料 |
| CRA | 监查 AE/SAE 记录是否完整、及时、可追溯 |
| 药物警戒/安全团队 | 接收 SAE，进行医学审核、监管上报和风险评估 |
| 安全医生 | 判断医学合理性、严重性、预期性、因果关系和风险信号 |
| 数据管理 | 清理 AE 数据，处理 query，确保数据库一致性 |
| 编码团队 | 使用 MedDRA 和 WHODrug 做标准化编码 |
| 统计团队 | 按 SAP 汇总安全性结果并生成 TFL |
| 医学写作 | 把安全性结果写进 CSR 并组织医学解释 |

## 关键概念

### AE

AE 是 Adverse Event，不良事件。它指受试者在试验期间发生的任何不利医学事件，不一定和试验药物有因果关系。

例子：

- 头痛
- 恶心
- 皮疹
- 肝酶升高
- 血压异常

### SAE

SAE 是 Serious Adverse Event，严重不良事件。常见判断标准包括：

- 死亡
- 危及生命
- 需要住院或延长住院
- 导致持续或显著残疾
- 先天异常或出生缺陷
- 其他医学上重要事件

### MedDRA 编码

MedDRA 是医学监管活动词典，用于把不同医生写法统一成标准术语。

例如“肚子疼”“腹部疼痛”“腹痛”可能需要归到统一的标准医学术语，方便统计和监管审阅。

### WHODrug 编码

WHODrug 用于标准化合并用药名称，帮助分析受试者同时使用的药物，以及可能的相互作用或混杂因素。

## 为什么安全性数据流要单独看

### 1. 时效性更强

疗效数据通常等数据库锁定后统一分析；但 SAE 可能需要在规定时间内快速上报监管机构、伦理委员会或合作方。

### 2. 有独立审核链路

AE/SAE 不只是 eCRF 中的一列数据。它们可能进入安全数据库，并由药物警戒和安全医生持续评估。

### 3. 直接影响试验和研发决策

如果出现新的风险信号，可能触发：

- 修改知情同意书
- 修改 protocol
- 暂停入组
- 增加安全监测
- 召开 DMC/IDMC 会议
- 向监管机构提交安全更新

### 4. 最后仍然要进入 CSR

CSR 的安全性章节通常会总结：

- 总体 AE 发生率
- 药物相关 AE
- SAE
- 导致停药的 AE
- 死亡
- AESI（特别关注不良事件）
- 实验室异常
- 生命体征和心电图异常
- 安全性结论和获益风险解释

## 关键理解

安全性数据流就是：**试验中所有风险信号如何被及时发现、标准化、医学判断、统计汇总，并最终写进 CSR。**

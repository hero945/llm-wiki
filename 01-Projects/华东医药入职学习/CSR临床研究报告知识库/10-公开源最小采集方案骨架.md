# 公开源最小采集方案骨架

## 定位

支撑 [[09-适应症机会briefing字段字典]] 中可公开采集的字段，优先官方 API，不依赖 SSR 硬爬。

实现代码已迁到 `C:\Users\admin\Desktop\workspace\indication-intel`（不含虚拟环境，运行前需本地 `pip install`）。

最小可行组合（MVP）：

1. ClinicalTrials.gov API — 试验路径与终点趋势  
2. openFDA / DailyMed — 竞品标签  
3. （可选第二批）PubMed E-utilities — 疾病/机制文献元数据  

内部 CSR / IB / RWD / 专家访谈不在本骨架范围。

## 一、目标字段映射

| Briefing 字段                                                  | 主数据源                     | 次数据源         |
| ------------------------------------------------------------ | ------------------------ | ------------ |
| `competitors[].name/status/key_endpoints`                    | ClinicalTrials.gov       | 标签（已批时）      |
| `competitors[].approved_indications/dose_regimen/key_safety` | openFDA Label / DailyMed | Drugs@FDA    |
| `endpoint_trends`                                            | ClinicalTrials.gov       | 文献           |
| `path.similar_dev_paths`                                     | ClinicalTrials.gov       | 指导原则 PDF（人工） |
| `disease.*` 文献支撑                                             | PubMed（第二批）              | 指南 PDF（人工）   |
| `SourceRef.*`                                                | 各 API 响应元数据              | —            |

## 四、API 调用要点

### 1. ClinicalTrials.gov API v2

- 文档入口：`https://clinicaltrials.gov/data-api/api`
- 常用：按 condition / term 检索 studies，再取 protocolSection
- 建议抽取：
  - `NCTId`
  - 简题 / 官方题
  - 阶段 `phases`
  - 总体状态 `overallStatus`
  - 适应症 `conditions`
  - 干预 `interventions`
  - 主要/次要终点 `primaryOutcomes` / `secondaryOutcomes`
  - 入排摘要（如有）
  - 申办方
- `SourceRef` 示例：
  - `source_type`: `trial`
  - `url`: `https://clinicaltrials.gov/study/{NCTId}`
  - `version_or_date`: 记录 `lastUpdatePostDate` 或采集日

注意：控制请求频率；结果缓存到 `data/raw/ctgov/YYYY-MM-DD/`。

### 2. openFDA Drug Label

- 端点：`https://api.fda.gov/drug/label.json`
- 常用检索：`openfda.brand_name` / `generic_name` / 全文 indication 关键词
- 建议抽取：
  - 药名（brand/generic）
  - `indications_and_usage`
  - `dosage_and_administration`
  - `boxed_warning` / `warnings_and_cautions`
  - `adverse_reactions`（可先存摘要级）
  - `effective_time` / `set_id`（若有）
- 细读权威原文时，用 DailyMed SPL（`setid`）回源，而不是只信 openFDA 拼接文本

注意：openFDA 有速率限制；生产环境建议申请 API key。

### 3. DailyMed（可选增强）

- REST：`https://dailymed.nlm.nih.gov/dailymed/services/v2/`
- 用途：按 `setid` 拉 SPL，核对适应症/用法章节原文
- 适合「竞品标签原文可追溯」场景

### 4. PubMed E-utilities（第二批）

- 用途：疾病定义、流行病学、未满足需求的文献元数据与摘要
- 产出进入 `supporting_evidence` / `guideline_refs` 的文献类 SourceRef
- 全文仍受版权限制，MVP 只采 PMID + 标题 + 摘要 + URL

## 五、标准化输出（normalized）

每条竞品/试验统一成：

```json
{
  "entity_type": "trial_or_label",
  "name": "",
  "company": "",
  "status": "phase3",
  "approved_indications": [],
  "key_endpoints": [],
  "key_safety": "",
  "dose_regimen": "",
  "geography": ["US"],
  "sources": [
    {
      "source_id": "SRC-CTGOV-NCT01234567",
      "source_type": "trial",
      "title": "",
      "url": "",
      "publisher": "ClinicalTrials.gov",
      "version_or_date": "2026-07-01",
      "excerpt": "",
      "accessed_at": "2026-07-13T08:00:00Z"
    }
  ]
}
```

`build_briefing_stub.py` 负责把 normalized 结果预填进 [[09-适应症机会briefing字段字典]] 的 JSON 模板：

- 自动填：`competitors`、`endpoint_trends` 候选要点、`sources`
- 留空给人工：`hypothesis.statement`、`conclusion.*`、`disease.unmet_need` 终稿表述

## 六、最小流水线步骤

```text
1. 读 queries.yaml
2. 拉 CT.gov → raw JSON
3. 拉开FDA labels → raw JSON
4. normalize → competitors / endpoint candidates / SourceRef
5. merge 进 briefing stub JSON
6. 人工审阅补全假设与结论
7. （可选）AI 生成 narrative briefing，但必须引用 SourceRef
```

## 七、验收标准（MVP Done）

- 给定 1 个适应症关键词，能产出 briefing stub JSON
- 至少包含 3 个竞品或同类试验条目（若公开库确有数据）
- 每条自动结论有可点击 `url` + `accessed_at`
- 不把 AI 叙述当作无来源；原始 API 响应可回放
- 无大规模 SSR；中国登记平台/说明书若后续加入，单独模块，不阻塞 MVP

## 八、明确不做（本阶段）

- 不爬出版社全文站
- 不入库完整 CSR/IB
- 不自动给出 go/no-go 终裁
- 不把 openFDA 文本未经核对直接当监管递交依据

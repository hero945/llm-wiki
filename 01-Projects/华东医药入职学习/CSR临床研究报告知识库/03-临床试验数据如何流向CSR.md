# 临床试验数据如何流向 CSR

CSR 不是直接写原始数据，而是引用经过**收集、清理、审核、锁库、标准化和统计分析**后的结果。

![[临床试验数据流向CSR.png]]

## 一句话流程

**源文件/病历 → eCRF/EDC → 数据清理和 query → 医学/安全审核 → 数据库锁定 → SDTM/ADaM → SAP 分析 → TFL → CSR**

## 每一步在做什么

| 节点           | 谁做               | 主要动作                  | 产出              | 为什么重要            |
| ------------ | ---------------- | --------------------- | --------------- | ---------------- |
| 1. 受试者与研究中心  | PI、研究者、CRC、受试者   | 记录访视、检查、用药、不良事件       | 病历、源文件、实验室报告    | 源文件是临床数据的原始依据    |
| 2. eCRF 录入   | 研究者、CRC          | 把关键数据录入电子病例报告表        | eCRF 数据进入 EDC   | 让分散的临床信息进入统一系统   |
| 3. 数据清理      | 数据管理、研究中心、CRA    | 处理缺失、异常、不一致，发起 query  | 清理后的临床数据库       | 降低错误，保证分析数据可信    |
| 4. 医学与安全审核   | 临床医生、安全医生、编码团队   | 审核 AE/SAE、合并用药、医学合理性  | 标准化医学判断和编码      | 保证安全性解释和统计口径一致   |
| 5. 数据库锁定     | 数据管理、统计、临床       | 确认数据冻结，不再随意修改         | Locked database | 正式统计分析需要稳定数据基础   |
| 6. 标准化与分析    | 统计师、程序员、CDISC 专家 | 转换 SDTM/ADaM，按 SAP 分析 | 分析数据集和结果        | 让数据符合提交、分析和审阅要求  |
| 7. TFL 与 CSR | 统计、医学写作、临床、安全    | 生成表、图、列表，并写入 CSR      | TFL 和 CSR       | 把数据结果变成可阅读、可审评证据 |

## 主数据流和安全性数据流

主数据流关注所有临床试验数据，例如：

- 人口学和基线特征
- 给药暴露
- 疗效指标
- 实验室检查
- 生命体征
- 心电图
- 合并用药
- 方案偏离
- 受试者完成和退出

安全性数据流关注风险相关数据，例如：

- AE（Adverse Event，不良事件）
- SAE（Serious Adverse Event，严重不良事件）
- 死亡
- 导致停药或退出的不良事件
- 特别关注不良事件 AESI
- 实验室、生命体征、心电图异常

安全性数据流详见：[[04-安全性数据流是什么]]

## CSR 中常见结果来自哪里

| CSR 内容 | 常见上游来源                   |
| ------ | ------------------------ |
| 研究设计   | Protocol                 |
| 统计方法   | SAP                      |
| 受试者处置  | eCRF、SDTM、TFL            |
| 基线特征   | eCRF、ADaM、TFL            |
| 疗效结果   | SAP、ADaM、TFL             |
| 不良事件   | eCRF、安全数据库、MedDRA 编码、TFL |
| 合并用药   | eCRF、WHODrug 编码、TFL      |
| 方案偏离   | 监查记录、临床确认、数据库            |
| 附录和列表  | TFL、Listings、关键文件        |

## 关键理解

### 1. CSR 写的是分析结果，不是原始记录

原始病历和源文件是证据起点，但 CSR 通常引用的是经过清理、锁库和分析后的结果。

### 2. 锁库是重要分界点

锁库前，重点是发现和修正数据问题。锁库后，重点是按 SAP 进行正式统计分析。

### 3. TFL 是 CSR 结果章节的主要来源

医学写作团队会基于 TFL 写结果叙述，并与 clinical、统计和安全团队一起解释结果。

# 计划：从成熟 Agent 平台经验到医药公司 AI 提效落地

> 核心判断：前公司的 Agent 平台玩法成立，是因为已经具备服务器、模型服务、MCP 工具能力、业务系统、权限审计和工程基建。当前公司的关键任务不是一开始搭建复杂 Agent 平台，而是先把基础数据、统一 AI 入口、高频痛点流程和最小 MVP 跑通，再逐步沉淀成可复用的 Agent 能力。

## 1. 前公司 Agent 平台玩法

前公司的环境更接近成熟企业级 Agent 平台建设：底层基础设施相对完善，模型可以私有化或自建，业务系统已经存在，MCP 能力也可以围绕内部系统持续封装。在这种情况下，Agent 的核心任务不是从零补数字化能力，而是把已有系统、已有数据和已有流程，通过 Skill、MCP、Workflow 等方式组织起来。

![[前公司-agent平台架构.png]]

一个成熟 Agent 平台通常可以拆成几层：

- 用户入口：Web、企业微信、飞书、内部系统等，让业务人员用自然语言发起任务。
- Skill List：把业务场景沉淀成可执行规程，例如退款、审批、工单、资料核对、报表生成。
- Agent Runtime：负责理解意图、选择 Skill、补齐参数、规划步骤、调用工具、生成结果。
- MCP 工具层：封装 CRM、ERP、数据库、知识库、审批系统、文档系统等企业能力。
- Workflow / 状态管理：处理长任务、审批、人审回调、失败重试、任务恢复和流程审计。
- 模型与基础设施：包括私有化大模型、向量数据库、日志监控、权限系统、成本统计和安全策略。

这种玩法适合体量较大、基建成熟、业务系统完整的公司。因为平台的价值来自“连接和编排已有能力”：已有数据可以查，已有系统可以调，已有权限可以继承，已有流程可以被 Agent 化。

换句话说，前公司的核心问题是：

> 如何把成熟业务系统转化成可被 Agent 调用、编排和审计的能力。

## 2. 当前医药公司现状与差异

当前公司的状态完全不同。这里并不是一个已经具备完整数字化底座、只差接入 Agent 的环境，而是一个更早期的阶段：

- 没有服务器或稳定的自建系统能力。
- 没有统一 AI 应用入口。
- 没有成熟的 MCP / API 工具体系。
- 数据和文档大概率分散在本地文件、微信群、表格、个人电脑、历史模板中。
- 流程依赖人工经验，但业务流程本身相对固定。
- 公司对 AI 的使用习惯、成本意识、权限边界和数据规范都还需要建立。

所以两类公司的建设逻辑并不一样：

| 维度 | 前公司 | 当前医药公司 |
| --- | --- | --- |
| 基础设施 | 已较完善 | 基本从零开始 |
| 模型能力 | 可自建或私有化 | 先使用托管模型或轻量方案更现实 |
| 业务系统 | CRM、ERP、审批、知识库等较成熟 | 可能缺少统一系统和 API |
| MCP 能力 | 可以围绕已有系统封装 | 需要等数据和流程稳定后逐步建设 |
| Agent 重点 | 平台化、编排、审计、权限 | 数据整理、流程提效、MVP 验证 |
| 成功标准 | 提升复杂流程自动化能力 | 先让真实岗位每天愿意使用 |

当前阶段最重要的不是“搭一个企业级 Agent 平台”，而是先完成从人肉流程到轻量数字化、再到 AI 辅助流程的过渡。

当前公司的核心问题是：

> 如何把分散文档、固定流程和人工经验，转化成可被 AI 使用、可统计、可复用、可持续迭代的工作流。

## 3. 推荐 Agent 提效建设步骤

### 阶段一：完善基础数据和流程资产

第一步不是写代码，而是盘清楚公司到底有哪些可被 AI 赋能的资产。

需要优先整理：

- 文档资产：SOP、制度、模板、说明书、注册资料、质量文件、销售材料、医学资料。
- 表格资产：客户表、项目表、资金计划、月报、流程台账、资料清单。
- 流程资产：谁发起、谁处理、谁审批、产出物是什么、常见异常是什么。
- 问题资产：业务同事反复咨询的问题、重复劳动、容易出错的节点。
- 权限资产：哪些资料可公开使用，哪些需要限制，哪些不能进入 AI 知识库。

这个阶段的目标不是把所有数据一次性治理完，而是先找到 2-3 个高频、固定、风险可控的流程。

### 阶段二：搭建统一 AI 使用入口

在没有成熟系统的情况下，统一入口比复杂 Agent 架构更重要。

建议先做一个轻量 AI 工作入口，用来统一承接公司内部 AI 使用：

- 统一用户入口：让大家从同一个入口提问和提交任务。
- 统一工具管理：先集成通用大模型、知识库问答、文档总结、表格处理等能力。
- 统一问题记录：沉淀用户问了什么、哪些问题高频、哪些问题回答不好。
- 统一成本统计：统计模型调用量、费用、部门使用情况、场景价值。
- 统一反馈机制：让用户标记“有用 / 无用 / 需要人工处理”。

这个入口不一定一开始就要自研很重，可以先用低代码平台、飞书/企微机器人、Dify、FastGPT、Coze、n8n、托管数据库等组合跑通。

关键是先把 AI 使用从个人零散尝试，变成组织可观察、可复盘、可管理的行为。

### 阶段三：基于真实使用数据选择 MVP

当统一入口运行一段时间后，就可以基于真实问题数据选 MVP，而不是凭感觉选题。

优先选择满足以下条件的场景：

- 高频：每天或每周反复发生。
- 固定：流程步骤相对稳定。
- 耗时：人工整理、核对、撰写成本高。
- 风险可控：AI 输出可以由人复核，不直接做高风险决策。
- 可衡量：能统计节省时间、减少错误或提高产出速度。

适合当前阶段的 MVP 方向包括：

- SOP / 制度问答助手。
- 文档编写提效助手。
- 模板化材料生成助手。
- 注册资料清单核对。
- 医学文献总结。
- 销售拜访记录整理。
- 月报 / 周报 / 项目进展初稿生成。
- 招投标或合同材料初步检查。

MVP 的目标不是做得很大，而是在一个小场景里证明：

> AI 能稳定进入真实流程，并让业务人员愿意持续使用。

### 阶段四：把有效 MVP 固化成可复用流程

MVP 跑通后，需要把成功经验固化下来，避免停留在“某个人会用 AI”的层面。

可以沉淀为：

- 标准 Prompt 模板。
- 文档输入格式。
- 输出模板。
- 人工复核规则。
- 常见失败案例。
- 场景使用说明。
- 成本和效果统计。

这一步相当于轻量版 Skill 化：先不急着做复杂的 Skill Runtime，而是把可复用经验整理成业务流程模板。

比如：

- 文档编写提效：输入背景资料，输出标准格式初稿。
- 模板输出：输入业务要点，输出合同、周报、项目计划、会议纪要。
- 资料核对：输入资料清单和文件，输出缺失项、异常项、待确认项。
- 医学支持：输入文献或资料，输出结构化摘要、风险点和待复核内容。

### 阶段五：逐步建设数据平台、Skill、MCP 和 Workflow

当基础数据、统一入口和 MVP 场景都稳定后，再逐步引入更工程化的 Agent 能力。

后续可以演进为：

- 数据平台：统一管理文档、表格、知识库、业务数据和访问权限。
- Skill 层：把高频业务流程写成标准化 Skill，明确适用场景、输入参数、执行步骤、输出格式和异常处理。
- MCP 层：当内部系统或数据表稳定后，再封装查询、写入、审批、归档等工具能力。
- Workflow 层：对于需要长任务、审批、审计、回调和状态恢复的流程，再引入工程编排。
- 监控与治理：统一统计使用量、成本、效果、失败率、部门采用情况和风险事件。

这个顺序很重要。当前公司不应该从最复杂的 Agent 平台开始，而应该从可见的业务价值倒推基础设施建设。

## 4. 未来展望

### 近期目标：90 天内形成真实使用

90 天内最重要的目标，是让公司出现 2-3 个真实岗位每天愿意使用的 AI 提效工具。

衡量标准可以是：

- 是否有稳定用户。
- 是否进入日常流程。
- 是否节省明确时间。
- 是否减少重复劳动。
- 是否形成可复用模板。
- 是否能通过数据证明价值。

### 中期目标：形成统一 AI 工作台

3-6 个月内，可以逐步形成一个轻量 AI 工作台：

- 统一入口。
- 统一知识库。
- 统一文档处理。
- 统一模板中心。
- 统一使用统计。
- 统一成本管理。
- 统一反馈和优化机制。

这个阶段的重点是让 AI 从“个人工具”变成“组织能力”。

### 长期目标：沉淀医药行业 Agent 能力

6-12 个月后，如果前面的基础建设和 MVP 结果成立，可以逐步沉淀更完整的医药行业 Agent 能力：

- 医药文档 Agent。
- 注册资料 Agent。
- 质量体系 Agent。
- 销售支持 Agent。
- 医学资料 Agent。
- 内部制度问答 Agent。
- 项目管理和材料归档 Agent。

长期来看，公司的 AI 能力不应只是聊天问答，而应该逐步演进为：

> 基于公司数据、业务流程和行业经验的可复用智能工作流。

## 行动清单

- 一周内：完成关键岗位访谈、资料盘点和 10 个高频痛点收集。
- 两周内：确定 1-2 个 MVP 场景，明确输入、输出、复核人和衡量指标。
- 一个月内：上线统一 AI 使用入口和第一个 MVP。
- 两个月内：基于真实使用数据优化 MVP，并沉淀模板和复核规则。
- 三个月内：完成 2-3 个流程试点，形成价值复盘和下一阶段建设路线。

## 个人判断

当前阶段最值得坚持的原则是：

1. 先让 AI 进入真实流程，再谈平台化。
2. 先治理最关键的数据，不追求一次性数据大而全。
3. 先做可衡量的 MVP，不做泛泛的聊天机器人。
4. 先沉淀模板和流程，再逐步抽象成 Skill、MCP 和 Workflow。
5. 先证明业务价值，再申请更多资源和基础设施投入。

最终目标不是复制前公司的 Agent 平台，而是结合当前医药公司的现实条件，走出一条从基础数据、统一入口、流程 MVP 到行业 Agent 能力的渐进路线。

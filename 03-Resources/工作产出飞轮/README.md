# 工作产出飞轮

把每次交付拆成可复用资产，下次任务必须先引用这些资产，而不是从空白再写一遍。

```text
做（项目里交付）
 → 交（给人看的成品）
 → 拆（术语 / 模板 / 决策 / 样例 / 反例）
 → 登（[[产出台账]] 记一行）
 → 用（下一份工作先查 [[可复用资产索引]]）
 → 改（用坏了就改资产，不要只改这一份文档）
```

这和公司级 Agent 平台不是一回事。当前阶段飞轮只服务你自己的两条主线：写作辅助、管线系统；子线入职学习给飞轮供料（术语、流程、痛点）。

## 什么算「转了一圈」

一次完整循环必须同时有：

1. 一份对外交付物（PRD、方案初稿、briefing、SOP、部署笔记……）
2. 至少 1 条回灌：新样例、新决策、新术语、或一条反例
3. 台账里多一行，并写清「下次可复用什么」

只写文档、不拆资产，飞轮停转。

## 三类回灌（只拆这三类，避免什么都收藏）

| 类型 | 放哪 | 例子 |
| --- | --- | --- |
| 决策 | 项目笔记或本索引「决策」 | 管线一期不做 SSO；M11 先抽元数据再生成章节 |
| 样例 | 项目 `样例/` 或 CSR briefing | synopsis → output JSON；GLP1 stub |
| 术语/模板 | 入职学习术语表、SOP、schema | CSR 缩写、PRD 标准、metadata_schema.yaml |

原文 PDF、一次性会议纪要不进飞轮，进 `参考资料/` 或 Inbox 后删除。

## 两条主线怎么转

**写作辅助**

```text
synopsis / 历史方案
 → 抽元数据（工具/metadata_extractor.py）
 → 生成章节初稿
 → 人工改稿
 → 把改对的字段和改错的字段回灌 schema / 样例 / 反例
```

**管线系统**

```text
Excel 模板 / 业务访谈
 → PRD / 蓝图 / 接口 / 原型
 → 默认决策清单
 → 下一期需求先对照决策，再改文档
```

**子线供料（不单独转圈）**

入职学习、CSR、研发流程负责把公司和行业语言喂给上面两条主线：术语进方案，SOP 进 PRD，痛点进 AI 场景。

## 每周最小动作（15 分钟）

周五用 [[每周复盘模板]]，只填飞轮三问：

1. 本周交了什么？（链到台账）
2. 拆出了哪 1–3 条资产？
3. 下周哪份工作会复用它们？
